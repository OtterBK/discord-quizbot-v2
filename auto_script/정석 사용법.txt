[systemd 서비스(quizbot3) 동작 방식 - 2026-08-15 정리]

quizbot3.service는 Type=simple이라 systemd가 ExecStart로 띄운 node dist/index.js 프로세스 하나를
"본체"로 추적한다.
- start: ExecStartPre(잔여 프로세스 청소, 아래 참고) → ExecStart(node dist/index.js 실행)
- stop: 본체가 속한 cgroup 전체에 SIGTERM → TimeoutStopSec(20초, 기본 90초에서 단축) 안에 안 죽으면
  SIGKILL → ExecStopPost(잔여 프로세스 청소)
- restart: stop 전체 과정 후 곧바로 start 전체 과정

quizbot_stop.sh 실행 후에도 ffmpeg/yt-dlp 같은 자식 프로세스가 간혹 안 죽는 문제(cgroup kill을
빠져나가는 경우가 있는 듯) 때문에, ExecStartPre/ExecStopPost 둘 다
auto_script/server_script/kill_orphan_quizbot.sh를 실행해서 남은 node/ffmpeg/yt-dlp 프로세스를
pkill -9로 확실히 정리한다. 이 훅은 서비스 유닛 자체에 박혀있어서 quizbot_start.sh/quizbot_stop.sh
같은 래퍼 스크립트를 거치지 않고 systemctl start/stop/restart quizbot3를 직접 쳐도 항상 같이
실행된다 - start 쪽 청소가 있어서, 이전 인스턴스가 완전히 안 죽은 채 새 start가 들어와도 중복 실행
없이 항상 깨끗한 상태에서 시작한다.

**주의**: 이 훅들은 auto_script/systemd/quizbot3.service.template에 있고, install_quizbot3.sh가 설치
시점에 한 번 /etc/systemd/system/quizbot3.service로 복사해서 생성한다. quizbot_update.sh(코드
업데이트)는 이 서비스 파일을 다시 생성하지 않으므로, 2026-08-15 이전에 이미 설치된 서버에 이 개선을
적용하려면 서비스 파일을 수동으로 다시 설치해야 한다:
  sudo sh -c "sed 's|__QUIZBOT_PATH__|$QUIZBOT_PATH|g' '$QUIZBOT_PATH/auto_script/systemd/quizbot3.service.template' > /etc/systemd/system/quizbot3.service"
  sudo systemctl daemon-reload

[한글 파일명이 `ls`에 물음표로 깨져 보일 때 - 2026-08-15 이전에 이미 설치된 서버]

UTF-8 locale 설정도 install_quizbot3.sh에만 있어서 기존 서버엔 소급 적용 안 됨 - 아래를 한 번만
실행하면 됨(재부팅/재로그인 불필요, 새 SSH 세션부터 바로 적용):
  sudo apt install -y locales
  sudo locale-gen en_US.UTF-8
  sudo update-locale LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
실제 파일 데이터는 이 설정과 무관하게 항상 UTF-8이라 봇 동작 자체엔 영향 없음 - 이건 순전히 `ls` 등
터미널 표시 문제였음.

  시나리오 지원).

  내부적으로 하는 일: quizbot3 중지 → git fetch + (브랜치 전환 시 checkout) + reset --hard
  origin/<선택한 브랜치> → npm install → custom_node_modules 패치 재적용 → npm run build →
  web-frontend npm install/npm run build(2026-08-15 추가) → **소유권을 ubuntu:ubuntu로 복원(2026-08-15
  추가)**. private_config.json/resources/log/dist/web-frontend/dist/node_modules는 전부 .gitignore
  대상이라 reset --hard로도 안 건드림(설정값·캐시 안전, resources/notices/의 quizmgr가 만든 공지와
  resources/maintenance_notice.txt(점검 모드)도 마찬가지). config/system_setting.js/
  resources/current_notice.txt/resources/banned_user.txt 3개는 git 추적 대상이지만 reset 전후로
  백업/복원해서 서버에서 직접 바뀐 값(로컬 설정 커스터마이징/quizmgr 실시간 공지 수정/실시간 밴 목록)이
  원복되지 않게 보호함(2026-08-15 추가·확장 — quizdata/bgm처럼 코드와 함께 배포돼야 하는 콘텐츠가
  아니라 서버별 운영 상태이기 때문. 단, 이 파일들에 새로 추가된 내용(예: 새 SYSTEM_CONFIG 필드)은 이
  방식으로는 자동 반영이 안 되니 origin의 최신 파일과 비교해서 수동 병합 필요). 이미 오래돼 사실상
  운영 콘텐츠로 안 쓰는 레거시 공지 2개(`resources/notices/`)는 git 추적에서 아예 제외해서, 관리자가
  quizmgr로 지워도 다음 업데이트 때 되살아나지 않게 함(2026-08-15).
  develop-claude 등 개발용 브랜치에서는 안전장치로 거부됨 — develop/master에서만 실행할 것.
  npm install/npm run build(루트든 web-frontend든) 실패 시 서비스를 시작하지 않고 중단하니, 에러
  메시지를 보고 고친 뒤 다시 실행할 것.

  **업데이트 완료 후 서비스가 자동으로 시작되지 않는다(2026-08-15 변경)** — 빌드/설정을 확인할 새도
  없이 바로 재시작되는 게 위험하다는 판단. 확인 후 quizbot_start.sh로 직접 시작할 것(스크립트 마지막에
  안내 문구로도 뜸).

  **소유권 문제(2026-08-15 이전 버전으로 이미 업데이트를 한 번이라도 돌린 서버)**: git
  fetch/reset/npm install/npm run build를 전부 sudo(root)로 실행하면서 이후 소유권 복원 단계가 없어서,
  손댄 파일이 전부 root 소유로 남는 버그가 있었음 — quizbot3.service는 User=ubuntu로 돌기 때문에,
  root 소유 파일을 봇이 쓰거나 지우는 동작(예: /quizmgr 공지 삭제)이 EACCES로 실패한다. 위 수정으로
  앞으로의 업데이트는 자동으로 해결되지만, **과거에 이미 생긴 root 소유 파일은 한 번 수동으로
  고쳐야 한다**:
    sudo chown -R ubuntu:ubuntu "$QUIZBOT_PATH"
