[구서버 → 신서버 이전 절차]

1. 구서버에서 config 폴더(config/private_config.json 등) 및 DB 백업(db_backup/*.sql)을 로컬로 백업

2. 신서버(GCP 등)에서 install_quizbot3.sh 다운로드 후 실행
   sudo bash install_quizbot3.sh

   설치 중 물어보는 것들:
   - 설치 경로 (필수)
   - Node.js 버전 (기본 22)
   - 설치할 브랜치 (기본 master, TS 마이그레이션이 반영된 최신 코드를 쓰려면 develop-v3.5 등으로 입력)
   - cron 등록 여부 (y 입력 시 아래 4번 스케줄이 자동 등록됨)
   - DB 백업 파일 경로 (1번에서 백업해둔 .sql, 비워두면 기본 base.sql 사용)
   - swap 메모리 크기 (선택)

   설치 스크립트가 자동으로 하는 것:
   - PostgreSQL/Node.js/Git 설치, DB 생성 및 복원
   - 저장소 clone (지정한 브랜치) → npm install → npm run build (TS를 dist/로 컴파일)
   - QUIZBOT_PATH를 /etc/profile.d/quizbot_path.sh 에 전역 등록
   - quizbot3 systemd 서비스 생성 + enable (아직 시작은 안 함)

3. 1번에서 백업해둔 config 폴더를 그대로 덮어쓰기
   (private_config.json은 .gitignore 대상이라 새로 clone한 환경엔 없음 — 반드시 복원해야 봇이 뜸)

4. cron 등록을 y로 답했다면 아래 스케줄이 자동 등록됨 (등록 내용은 install_quizbot3.sh 참고):
   - 매시 정각: drop_ffmpeg.sh (5분 이상 살아있는 orphan ffmpeg 강제 종료)
   - 9시/21시: quizbot_stop.sh → update_yt-dlp.sh → (1분 뒤) quizbot_start.sh (하루 2번 재시작)
   - 매주 월 0시: reset_played_count_of_week.sh
   - 8시/20시: backup_script.sh (DB 덤프, 7일 지난 백업 자동 삭제)
   - 3시간마다: sync && drop_caches

5. auto_script/server_script/quizbot_start.sh 로 봇 실행 (내부적으로 systemctl start quizbot3)

[운영 중 확인/조작]

- 상태 확인:      sudo systemctl status quizbot3
- 실시간 로그:     journalctl -u quizbot3 -f
- 수동 재시작:     sh auto_script/server_script/quizbot_stop.sh && sh auto_script/server_script/quizbot_start.sh

[코드 업데이트 시 (신규 기능/버그수정 반영, develop/master 브랜치 전용)]

  sh auto_script/server_script/quizbot_update.sh

  내부적으로 하는 일: quizbot3 중지 → git fetch + reset --hard origin/<현재 브랜치> → npm install →
  custom_node_modules 패치 재적용 → npm run build → quizbot3 재시작. private_config.json/resources/
  log/dist/node_modules는 전부 .gitignore 대상이라 reset --hard로도 안 건드림(설정값·캐시 안전).
  develop-claude 등 개발용 브랜치에서는 안전장치로 거부됨 — develop/master에서만 실행할 것.
  npm install/npm run build 실패 시 서비스를 시작하지 않고 중단하니, 에러 메시지를 보고 고친 뒤 다시
  실행할 것.
