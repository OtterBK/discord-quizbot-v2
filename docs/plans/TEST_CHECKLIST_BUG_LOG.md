### ✅ [E] 랜덤(오마카세) 퀴즈 진행 중 크래시 — `Cannot read properties of null (reading 'quiz')`

- 재현 조건: 2026-08-14 02:01경 실사용 테스트 중(guild_id: 733548069169397842) 랜덤 퀴즈 진행 중 노래
  맞추기 문제(question_id: 1946) 준비 단계에서 발생. yt-dlp 다운로드가 여러 번 연속 실패한 직후로 보임
  (`AudioCacheManager`가 같은 시간대에 "Failed yt-dlp download" 경고를 반복 기록, DNS 실패/403 등).
  정확한 재현 스텝은 미확정 — 로그로만 발견, 사용자가 직접 재현 스텝을 보고한 건 아님.
- 실제 동작: 서버 로그에 다음 스택트레이스와 함께 크래시 발생 →
  `TypeError: Cannot read properties of null (reading 'quiz')`
  `at Prepare.generateAudioResourceFromWeb (dist/quizbot/quiz_system/lifecycle/prepare.js:476:55)`
  `at async Prepare.prepareCustom (.../prepare.js:332:129)`
  이후 클러스터가 죽고 `ShardManager`가 `Launched Cluster 0`으로 자동 재기동, 마스터 프로세스까지
  전체 재시작된 것으로 보임(`Web Session Manager initialized`/DB 재연결 로그가 그 직후 다시 찍힘) —
  진행 중이던 퀴즈 세션은 그 과정에서 다 날아갔을 것으로 추정.
- 기대 동작: 오디오 다운로드가 연속 실패해도(네트워크 문제 등) 죽은 참조 접근 없이 "이 문제를
  건너뜁니다" 처리로 안전하게 넘어가야 함.
- 심각도: **진행 차단급(크래시)**.
- **2026-08-14 추가 정보(사용자)**: 퀴즈 진행 중 "그만두기"(force stop) 버튼으로 강제 종료할 때 가끔
  이 유형의 에러가 뜬다고 함.
- **원인+수정 완료(2026-08-15)**: `prepare.ts`의 `generateAudioResourceFromWeb`이 yt-dlp 다운로드
  `await` 도중 "그만두기"로 세션이 `free()`되면(`quiz_session.ts:142`가 `option_data`를 null로 초기화)
  await가 재개된 뒤 `option_data.quiz.audio_play_time`을 읽다가 크래시 — 정확히 사용자가 짚었던
  force-stop 타이밍 레이스였음. `option_data`가 null이면 다른 실패 케이스와 동일하게 `[undefined,
  undefined, 에러메시지]`를 반환하며 조용히 스킵하도록 null 체크 추가.
