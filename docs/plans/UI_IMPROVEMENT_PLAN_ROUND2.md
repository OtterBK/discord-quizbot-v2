## B. 화면별 UX/편의성 개선 후보

우선순위 태그: **[P1]** 사용자가 자주 마주치는 혼란/불편, **[P2]** 있으면 좋음(편의 기능), **[P3]** 참고용(고치지 않아도 무방).

### B-1. 봇 전역 에러/온보딩 — ✅ 전체 항목 수정 완료 (2026-08-12)

- ✅ **[P2] 도움말/온보딩이 전혀 없음.** `/도움말` 같은 명령어 없음, 봇이 새 서버에 들어갔을 때 안내 메시지(`guildCreate` 리스너) 없음. 새 유저는 Discord가 보여주는 슬래시커맨드 한 줄 설명이 안내의 전부. → `/도움말` 슬래시커맨드 신설(`command_manager.ts`/`bot.js`의 `help_handler`, 관리자 전용 명령어는 의도적으로 안내에서 제외) + `client.on('guildCreate', ...)` 신설(시스템 채널 우선, 없으면 메시지를 보낼 수 있는 첫 텍스트 채널로 폴백).
- ✅ **[P2] 인터랙션 타임아웃이 완전히 침묵.** 만료된 버튼을 누르면 `bot.js`가 `deferUpdate()`만 시도하고 실패하면 조용히 무시 — "이 버튼은 만료됐어요, 메뉴를 다시 열어주세요" 같은 안내가 없음. → `deferUpdate()` 성공 시 `followUp()`으로 안내 메시지 추가, 실패 시(토큰 자체가 만료돼 응답 불가능한 경우)는 로그만 남기도록 변경.
- ✅ **[P3] `/퀴즈정리`(강제 세션 정리)가 확인 절차 없이 즉시 전체 세션을 지움.** 관리 목적 명령어라 실사용 빈도는 낮지만, 진행 중인 사람이 있는지 미리 보여주지 않음. → 확인/취소 2버튼 프롬프트 추가(다른 화면의 파괴적 동작 확인 패턴과 동일), 확인 후 결과는 기존과 동일하게 채널에 공개로 안내(진행 중이던 다른 참가자도 알 수 있게).
- ✅ **[P3] 모든 봇 메시지가 🔸 하나로 정보/에러/성공을 뭉뚱그려 표현.** 심각도별 구분이 이모지 선택에만 의존. → `bot.js` 범위 안에서 🔸(안내)/⚠️(실패·제한)/✅(성공) 3단계로 구분. **`bot.js`만 정리했고 `quiz_ui/*` 등 나머지 파일은 아직 미적용** — 전체 스윕은 범위가 커서 별도 후속 작업으로 분리.
